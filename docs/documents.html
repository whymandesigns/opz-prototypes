Adding documents

Documents can be added in two ways:

MethodHow it works
Paste a URL Paste any link — Google Doc, Notion page, Figma file, Confluence page, or any URL. Operationalize fetches the page title automatically. The document opens in its original tool when clicked.
Upload a file Upload PDFs, images, or office files (up to 50 MB). Files are stored securely and accessible to anyone with access to the initiative. Uploaded files can be downloaded directly from Operationalize.
Supported integrations Google Workspace (Docs, Sheets, Slides, Drive), Notion, Confluence, Figma, and Loom links are enriched with metadata — title, last-modified date, and a preview thumbnail where available. Plain URLs work too, just without the enrichment.

Labels and groups

Each document can have a label (a short tag like PRD, Deck, Design, Brief) and belong to a group (a freeform section heading). Use groups to organize documents when there are more than 4–5 of them.

Common group structures:

  • Strategy — PRDs, OKR docs, exec briefs
  • Design — Figma files, design specs, UX research
  • Engineering — Tech specs, architecture diagrams, RFCs
  • Legal / Compliance — Contracts, certifications, privacy assessments

Pinning key documents

Pin up to 3 documents to surface them at the top of the list and include them in the initiative summary card. Pin the documents that every stakeholder reviewing this initiative should read first — typically the PRD and the kickoff deck.

Best practices

Link, don't copy Always link to the live document rather than uploading a snapshot. This ensures reviewers always see the latest version, not a stale copy from the day the initiative was created.
Check document permissions Operationalize stores the URL but doesn't change the access settings of the linked document. If a stakeholder clicks a Google Doc link and sees "Request access," the doc is restricted in Google. Ensure documents are shared with the right people in their source tool.
