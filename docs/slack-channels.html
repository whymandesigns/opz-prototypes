Channel types

When you link a Slack channel, you set a role for it. The role determines what Operationalize posts to the channel.

RoleWhat gets posted
Primary All initiative updates: status changes, blocker flags, new document links, and meeting agenda previews. Intended for the core team working on the initiative.
Digest Weekly status digest only — a single Friday message summarizing progress, KR scores, and upcoming milestones. Good for leadership or stakeholder channels.
Alerts only Only posts when status changes to At Risk or Off Track. Useful for on-call or escalation channels that should only be notified when something needs attention.

Connecting your Slack workspace

Operationalize uses the Slack OAuth integration to search channels and post messages. If your workspace isn't connected yet, an admin needs to authorize it first.

1
Admin authorizes the Slack app
Go to Admin Settings → Integrations → Slack and click "Connect Workspace." This is a one-time step per workspace. The Operationalize bot is added to your Slack org.
2
Invite the bot to channels you want to use
In Slack, type /invite @Operationalize in any channel you plan to link. The bot needs to be a member before it can post there.
3
Link channels from the initiative
Back in Operationalize, open the Slack Channels section of your initiative and search for the channel by name. Channels where the bot is a member will appear in the results.

Best practices

One primary channel per initiative Don't link five channels as Primary — you'll fragment the conversation. Pick the one place your team already communicates about this work and set it as Primary. Use Digest or Alerts for everything else.
Avoid linking private channels Operationalize can post to private channels where the bot is a member, but channel name search only returns public channels. To link a private channel, copy its Slack channel ID (starts with C) and paste it into the search box directly.
